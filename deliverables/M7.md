## 3. Step-by-Step Verification Commands

Run these commands in Phase 2 to initialize, plan, provision, verify, and tear down your AWS infrastructure in `ap-south-1`:

```bash
cd terraform

# 1. Initialize Terraform providers
terraform init

# 2. Validate HCL syntax and formatting
terraform fmt -check
terraform validate

# 3. Generate execution plan
terraform plan -out=tfplan

# 4. Provision VPC and EKS cluster in ap-south-1 (takes ~12-15 minutes)
terraform apply tfplan

# 5. Configure kubectl to connect to the provisioned EKS cluster
aws eks update-kubeconfig --region ap-south-1 --name cloudledger-eks-cluster
kubectl get nodes -o wide

# 6. AFTER completing M8/M9/M10 screenshots, destroy all AWS resources cleanly
terraform destroy -auto-approve
cd ..
```

## 5. Written Explanations / Submission Notes

**AWS VPC & EKS Architecture (`ap-south-1`):**
The Terraform configuration provisions a dedicated `10.20.0.0/16` VPC spanning two Availability Zones in `ap-south-1`. Public subnets (`10.20.1.0/24`, `10.20.2.0/24`) host the Internet Gateway and NAT Gateway (tagged with `kubernetes.io/role/elb = 1`), while private subnets (`10.20.11.0/24`, `10.20.12.0/24`) isolate the EKS managed worker node group (`cloudledger-managed-nodes`) from direct inbound internet traffic. Zero static AWS keys are stored in `.tf` files; authentication relies entirely on standard AWS CLI environment/profile credentials.
